# عقود التدقيق — V1

هذه الحزمة تستهدف `net10.0` ولا تحتوي مراجع حزم أو مشاريع. تعتمد فقط على مكتبات .NET، ومنها `System.Text.Json`. لا تحتوي كيانات أعمال أو EF Core أو MassTransit أو مراجع إلى IdentityService أو AuditService. لا تنشئ قاعدة بيانات ولا تنشر رسائل بنفسها.

## فصل metadata عن التاريخ

الحقول `CreatedBy`, `CreatedAt`, `LastModifiedBy`, `LastModifiedAt` أعمدة عادية داخل جدول كل كيان أعمال ينطبق عليه التدقيق في قاعدة الخدمة المالكة، بجوار مفتاحه. تملؤها الخدمة محليًا أثناء الحفظ. لا تخزن هذه الحقول في جدول مركزي بديل، ولا تحدث عبر RabbitMQ، ولا يعتمد حفظها على توفر AuditService.

AuditService المستقبلية تملك التاريخ المركزي في AuditDb مستقلة. لا تعدل بيانات الخدمات الأخرى. تحتفظ IdentityService أيضًا بسجلات الأمن الحرجة محليًا. لا يُولد حدث تلقائي لكل `SaveChanges`؛ يُلتقط فعل أعمال ذو معنى، وتُستبعد العمليات التي لم تغير شيئًا. لا تضاف أعمدة metadata أو migrations في هذه المرحلة.

## شكل العقد والتحقق

العقد هو `Audit.Contracts.V1.AuditEventRecordedV1`. أسماء JSON مثبتة بصيغة camelCase، والتعدادات نصوص بأسماء ثابتة وليست أرقامًا. أزيلت fixture التحقق المؤقتة مع مشروع اختبارها في تنظيف نهاية اليوم؛ يلزم إنشاء اختبارات توافق دائمة عند استئناف العمل.

| الحقل | القاعدة وحد الطول المقترح في V1 |
| --- | --- |
| `eventId` | مطلوب، UUID غير فارغ يولد مرة لكل حدث منطقي قبل حفظه في outbox |
| `sourceService` | مطلوب، معرف مصدر ثابت لا اسم instance أو hostname؛ أقصى 64 حرف ASCII |
| `applicationId` | مطلوب، التطبيق الذي تخصه العملية؛ أقصى 100 حرف ASCII |
| `tenantId` | nullable، أقصى 128 حرفًا؛ مطلوب عندما يكون الحدث تابعًا لمستأجر |
| `actorKind` | مطلوب: `User`, `System`, `Anonymous` |
| `actorUserId` | nullable، أقصى 450؛ مطلوب للفاعل البشري الموثق فقط |
| `actorUserNameSnapshot` | nullable، أقصى 256؛ لقطة عرض موثوقة وليست مرجع الهوية |
| `actorSystemId` | nullable، أقصى 128؛ مطلوب للفاعل النظامي فقط |
| `action` | مطلوب، كود فعل ثابت مستقل عن أسماء controllers؛ أقصى 160 حرف ASCII |
| `entityType` | مطلوب، نوع مورد منطقي ثابت؛ أقصى 128 حرف ASCII |
| `entityId` | nullable، أقصى 450؛ مطلوب مع `Committed`، ويمكن أن يغيب عن محاولة لم تحدد موردًا |
| `timestampUtc` | مطلوب، وقت حدوث الفعل في المصدر، غير افتراضي وoffset صفر |
| `ipAddress` | nullable، IPv4/IPv6 مطبع، أقصى 45؛ من connection بعد trusted proxy middleware |
| `deviceName` | nullable، أقصى 128؛ وصف غير موثوق ولا يثبت هوية الجهاز |
| `userAgent` | nullable، أقصى 1024؛ metadata غير موثوقة |
| `correlationId` | مطلوب، أقصى 128 حرف ASCII؛ معرف تتبع غير سري وليس هوية أمنية |
| `oldValues`, `newValues` | nullable، كائن مفاتيح صريحة وقيم JSON مسموحة لكل فعل |
| `status` | مطلوب: `Committed`, `Denied`, `Failed` |

القيم المطلوبة ليست null أو فارغة أو whitespace. القيم الاختيارية إما null/غائبة أو قيمة غير فارغة ضمن الحد. معرفات المصدر والتطبيق والمستأجر والكيان تقارن مقارنة ordinal ثابتة دون تغيير حالة الأحرف أو trim صامت. تسجل الخدمات معرفات canonical من بياناتها الموثوقة. لا يعني `tenantId = null` جميع المستأجرين؛ يعني حدثًا على مستوى التطبيق، ويحتاج grant منفصلًا.

`SourceService` يحدد **من أنتج الحدث**، و`ApplicationId` يحدد **لأي تطبيق ينتمي الحدث**، و`TenantId` يحدد **أي مستأجر داخل التطبيق**. قد تنتج خدمة واحدة أحداث تطبيقات متعددة. لا يكفي تطابق اسم الخدمة لإثبات النطاق. يجب لاحقًا التحقق من المصدر عبر broker topology وصلاحياته، ومن التطبيق والمستأجر عبر بيانات المصدر وسياسات قبول المصدر، لا من request headers اعتباطية.

حد payload المبدئي 64 KiB من UTF-8 JSON، بعمق JSON أقصى 16. يجب تحديد عدد مفاتيح وقيم change sets المسموح بها لكل فعل. يرفض المنتج والمستهلك لاحقًا الأحجام والمفاتيح والأنواع غير المسموحة قبل التسجيل. هذه حدود تكامل، وليست فحوصًا تلقائية داخل DTO.

**حد التحقق الحالي:** `required` وSystem.Text.Json يرفضان الحقول المطلوبة الغائبة، والصيغ غير القابلة للتحويل، والأرقام أو النصوص غير المعروفة للتعدادات. لا يمنع DTO وحده null الصريحة في strings أو UUID فارغًا أو وقتًا غير UTC أو تركيبة فاعل غير صحيحة أو حقولًا حساسة. تطبيق التحقق الدلالي أعلاه إلزام على المنتج والمستهلك في مراحل التكامل؛ لا توجد في الحزمة طبقة تحقق أعمال أو serializer عام للكيانات. لا يجوز اعتبار نجاح deserialization إثباتًا لصحة الحدث أو الثقة به.

## الوقت والمعرفات والفاعل

- `TimestampUtc` هو وقت الفعل في المصدر، يلتقط قبل commit قريبًا من التغيير، وليس وقت commit الدقيق أو وقت وصول الرسالة. لا يغير أثناء retries. يحفظ AuditService الوقت كما هو، ويضيف `IngestedAtUtc` محليًا لاحقًا. لا يرسل المصدر وقت ingestion. تُراقب فروق ساعات الخدمات، ولا تصحح أحداثًا قديمة بصمت.
- `EventId` لا يعاد توليده عند redelivery أو إعادة تشغيل outbox أو نقل الحدث إلى error queue وإعادته. فعل جديد أو محاولة مستقلة لها معرف جديد. فشل معاملة قبل commit لا ينتج حدث `Committed`. إعادة إرسال HTTP بعد نتيجة commit مجهولة تتطلب business idempotency مستقلة؛ معرف الحدث لا يحلها.
- `CorrelationId` مستقل عن EventId: يمكن لأحداث متعددة مشاركة trace واحد. يستخدم W3C trace-id canonical إذا توفر trace صالح، وإلا يولد معرف تتبع جديد وينتقل مع العمل الخلفي. لا يستخدم كرمز وصول أو مفتاح إزالة تكرار. يُقيد ويُنقح الإدخال الخارجي ولا يسجل بيانات سرية.
- `User`: معرف المستخدم من principal موثق؛ `actorSystemId` يجب أن يكون null. snapshot الاسم من بيانات الخادم؛ إذا لم تتوفر فلا تخترع. لا تسجل قيمة login المدخلة كهوية موثقة.
- `System`: `actorSystemId` ثابت مثل `identity-service:permission-seed`؛ معرف المستخدم وsnapshot اسمه null. لا تنشئ principal HTTP وهميًا للـconsumer.
- `Anonymous`: معرفا المستخدم والنظام وsnapshot الاسم null. غياب الفاعل البشري لا يبرر إسناد حساب موجود اعتمادًا على اسم ادعاه العميل.
- العمل الخلفي الذي ينفذ فعلًا طلبه مستخدم يمكنه الحفاظ على سياق ذلك المستخدم من رسالة داخلية موثوقة. لا يعيد استخدام السياق كدليل صلاحية لتنفيذ عمل جديد؛ العمليات النظامية المستقلة تنسب إلى النظام.
- `DeviceName` لا يعبر عن اسم Windows مثبت. `UserAgent` وdevice metadata لا يثبتان الهوية. لا تستخدم reverse DNS أو headers اعتباطية كمصدر موثوق.

## القيم المسموحة والخصوصية

`OldValues` و`NewValues` نوعهما `IReadOnlyDictionary<string, JsonElement>?` ليكون المستوى الأعلى كائنًا صريح المفاتيح. لا يوجد تحويل تلقائي من entity أو request أو ChangeTracker. يُنشئ handler change set محددًا، ويستخدم قوائم سماح خاصة بـ`SourceService + Action + EntityType`. مثال: `permissionCodes` قبل وبعد تعديل منح الدور. مفاتيح وقيم المصفوفات وترتيبها ومعنى null والحذف تحدد لكل action؛ تعني القيمة null داخل الخريطة قيمة حقل null، بينما غياب الخريطة يعني عدم توفير قيم مقارنة.

لا تنسخ passwords أو hashes أو tokens أو OTPs أو مفاتيح أو credentials أو بيانات دفع حساسة أو request bodies إلى الحدث. لا تكفي قائمة منع عامة لضمان ذلك. تلزم مراجعة source allowlists والتحقق عند الاستقبال وتقييد logs وerror queues والنسخ الاحتياطية. عند إنشاء JsonElement من JsonDocument مؤقت، استخدم `Clone()` قبل التخلص من المستند. لا تعدل الخرائط بعد تسليم الحدث لمسار outbox؛ record وIReadOnlyDictionary لا يضمنان deep immutability.

## التسليم والذرّية والفشل — التزام المراحل اللاحقة

معاملة المصدر تجمع بيانات الأعمال وmetadata الكيان والسجل الأمني المحلي المطلوب وحدث outbox. أي فشل قبل commit يلغيها معًا. يرسل MassTransit بعد commit إلى RabbitMQ، ثم يكتب consumer الحدث وreceipt ذريًا في AuditDb. تعطل broker أو AuditService لا يمنع commit المحلي ما دام التخزين المحلي متاحًا. لا distributed transaction أو اتصال من AuditService بقاعدة المصدر.

التسليم at-least-once. مفتاح إزالة التكرار الدائم هو `(SourceService, EventId)` مع payload fingerprint canonical؛ نفس المفتاح والمحتوى لا ينشئ تاريخًا جديدًا، ونفس المفتاح بمحتوى مختلف يعزل كحادث ولا يستبدل التاريخ. لا تعتمد الإزالة فقط على نافذة inbox المؤقتة. وصول الأحداث خارج الترتيب مقبول؛ لا يعني ترتيب التقرير ترتيب commit سببيًا بين الخدمات.

`Committed` يعني أن معاملة المصدر التزمت، و`Denied` يعني رفضًا أمنيًا دون تغيير الأعمال، و`Failed` يعني فشل المحاولة دون نجاح ملتزم. لا يستبدل Failed حدث نجاح لعملية التزمت ثم فشل إرسال response؛ التزام قاعدة البيانات هو المرجع. محاولات الرفض أو الفشل تحتاج معاملة تسجيل مستقلة بعد rollback، مع سجل محلي وoutbox عند توفر قاعدة المصدر. انقطاع SQL نفسه لا تحله معاملة ثانية في القاعدة نفسها. ضمان تسجيل تلك الحالة بالكامل ما زال قرارًا مفتوحًا؛ لم يعتمد collector خارجي ولم ينفذ. لا ندعي durable capture من stdout أو memory queue. التغييرات الملزمة بالتدقيق تفشل مغلقًا إذا تعذر حفظ أثرها المحلي.

## التفويض المركزي للتقارير

التقارير تخص AuditService وحدها. **المصدر الدائم المعتمد تصميميًا لهويات المستخدمين ومنح التقارير ونطاقات التطبيق/المستأجر هو IdentityService** بوصفه مالك التفويض، عبر مخزن grants محفوظ في IdentityDb وعقد تحقق داخلي محمي بهوية خدمة. هذا قرار تصميم للمرحلة اللاحقة، ولا يضيف جداول أو endpoints في المرحلة الأولى. لا تصبح static configuration مخزن التفويض الدائم. إعدادات المصادر الموثوقة في broker منفصلة عن منح المستخدمين.

يمثل grant لاحقًا صلاحية مثل `Audit.Reports.Read` ونطاق تطبيق ومستأجرين ومصادر مسموحة، مع صلاحية مستقلة لmetadata الحساسة. لا يعطي اسم دور Administrator تجاوزًا. تستخدم AuditService نتيجة تفويض موثوقة وحديثة، وتطبق تقاطع النطاق على كل query والتفاصيل والمجاميع والصفحات؛ تفشل مغلقًا عند تعذر القرار. لا تثق في tenant المرسل من العميل، ولا تعتبر null wildcard. لا تدير AuditService صلاحيات أعمال الخدمات. إدخال خدمة جديدة ضمن scopes موجودة لا يحتاج تعديل شيفرة IdentityService؛ التغييرات تكون بيانات grants وتسجيل مصدر معتمد.

التفاصيل غير المحسومة قبل مرحلة التقارير: schema النطاقات، إدارة grants والتفويض المفوض، هوية الخدمة وaudience لعقد التحقق، provisioning والـbootstrap، وسياسة أي cache وحد سحب الصلاحيات. لا يجوز نشر تقارير متعددة المستأجرين قبل اعتمادها واختبارها.

## الاحتفاظ وإصدارات العقد

- يحتفظ AuditService بالأحداث الساخنة وفق مدة معتمدة ثم يؤرشفها مع timestamps وهوية الحدث والنطاق، مع legal holds وحماية PII. اقتراح 12 شهرًا ليس سياسة نافذة.
- receipts تحتفظ بمفتاح المصدر/الحدث وبصمة المحتوى دون نسخ before/after أو IP أو snapshot الاسم. يجب أن تغطي مدة بقائها كامل فترة إمكان replay، بما فيها outbox وerror queues وarchives واستعادة backups، ويمكن أن تتجاوز مدة الأحداث الساخنة.
- أرشفة الحدث لا تحذف receipt. لا يحذف receipt آليًا بعمر الحدث. إذا أجيز replay غير محدود يجب حفظ receipts بلا حد أو اعتماد آلية rejection/restore أخرى. لا يمكن ضمان عدم التكرار بعد حذف receipt مع استمرار قبول replay القديم. مدة replay وسياسة حذف receipts وتكلفة التخزين قرارات يجب اعتمادها قبل retention jobs.
- هوية العقد هي namespace والنوع `Audit.Contracts.V1.AuditEventRecordedV1`، وليست رقم إصدار package فقط. يلزم تثبيت message identity/routing لاحقًا دون وضع attributes خاصة بـMassTransit هنا.
- أسماء JSON وأنواعها والتعدادات ومعانيها ثابتة في V1. يسمح بحقول جديدة اختيارية ذات معنى افتراضي آمن فقط. يقرأ V1 الحقول غير المعروفة ويتجاهلها؛ لذلك لا تعتمد ميزة أمنية جديدة على حقل يتجاهله مستهلك قديم.
- إضافة required property أو enum member جديد أو تغيير معنى null أو توسيع حدود قد يرفضها قارئ قديم أو تغيير شكل change set لفعل موجود يحتاج V2 أو action جديدًا مراجعًا. لا تحذف أو تعيد تسمية حقول V1.
- أرقام enum الداخلية لا تستخدم على wire. JSON يرفض القيم الرقمية والنصوص غير المعروفة. golden fixture تبقى baseline تاريخية ولا تحدث لإخفاء تغيير كاسر.
- يتطلب V2 خطة تشغيل القارئين وتوجيه الرسائل وتصريف V1 القديمة، لا dual processing لحدث واحد ينتج سجلين.

## التحقق والنطاق الحالي

أزيل مشروع التحقق التنفيذي المؤقت بطلب المستخدم في تنظيف نهاية اليوم. سجل نجاح اختبارات العقود الـ26 تاريخي، ولا يوجد حاليًا runner لهذه الاختبارات ضمن solution. بناء الحزمة مستقل:

```powershell
dotnet build Audit.Contracts/Audit.Contracts.csproj -c Release
```

يجب أن تغطي الاختبارات الدائمة لاحقًا fixture ثابتة، وأسماء wire والتعدادات، وrequired fields، وoptional/additive compatibility، وUUID/time parsing، وUTC round-trip precision، وchange value shape، والعربية وأنواع JSON، وreplay identity، ونظافة اعتماد assembly. لا تدعي نتائج التحقق السابقة اختبار SQL أوbroker أوenforcement دلالي غير منفذ.

قبل المرحلة الثالثة يجب إعادة التحقق من إصدار MassTransit وتوافق net10/EF Core وتراخيصه واعتماد التكلفة؛ لا توجد حزم messaging هنا. لا ينشأ AuditService أو reporting API أو migrations أو broker configuration في هذه المرحلة.
